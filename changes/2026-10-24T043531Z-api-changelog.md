 Origin API Changelog
 The Origin API is in Early Beta and subject to change. Review the OpenAPI specification when updating an integration.
 Changes to the Origin public API, including endpoints, request and response schemas, scopes, and webhooks, grouped by day with the newest first. Each change carries one label: Breaking, Deprecated, Added, Changed, or Removed. Breaking and deprecated changes include migration guidance inline. The Origin API reference always reflects the latest synced state.
+October 23, 2026
+Breaking. Get Repo Tarball returns PermissionDenied (HTTP 403) to an installation access token or an installation user token that calls from an address outside the inbound IP allowlist of the namespace the app is installed in, while that namespace enforces the list. These requests used to receive the 302 redirect, whose download URL only listed addresses could use. Migration: call Get Repo Tarball from an address on the installation namespace's allowlist, as you already do to download the archive.
+Deprecated. users and groups are deprecated in favor of the new reviewers list and will be removed in a future release. This covers the request bodies of Request Pull Request Reviewers and Remove Pull Request Requested Reviewers and the responses of List Pull Request Requested Reviewers and Request Pull Request Reviewers. Both are still accepted and populated as before, and the request lists remain the only way to name a user by email or a group by slug. Migration: send and read reviewers, and keep users and groups only for email and slug lookups.
+Added. List Pull Request Requested Reviewers and Request Pull Request Reviewers responses include reviewers, which lists every requested reviewer, service accounts included. Each entry sets exactly one of user, group, or serviceAccount, the shape reviewer has in the Pull Request Reviewer Events payload. A requested service account stays listed until it submits a review at or after the request.
+Added. Request Pull Request Reviewers and Remove Pull Request Requested Reviewers accept reviewers, which names each reviewer by public ID as a user (user_…), group (grp_…), or serviceAccount (sa_…), so you can request and remove bot service accounts. A requested service account must be a bot whose owner belongs to the team that owns the repository. One the repository can't request returns PermissionDenied (HTTP 403), and one that can't review the pull request, such as a personal bot on a pull request its owner authored, returns FailedPrecondition (HTTP 400).
+October 22, 2026
+Breaking. Get Repo Tarball responds 302 to every request made with an installation access token, an installation user token, or a service account, and the download URL in Location accepts requests only from addresses on the inbound IP allowlist of the repository's namespace while the namespace enforces one. For a service account, the allowlist of the team that owns the account applies too, and a request from an address that allowlist excludes returns PermissionDenied (HTTP 403) instead of the redirect. The first request for a commit used to stream the archive with 200, which an installation user token could do from any address. Migration: read the archive from the URL in Location instead of the response body, and download it from an address on the namespace's allowlist.
+Added. Apps can request namespace:repositories:create, and an installation that holds it can create repositories in its namespace with Create Repo. The installation must use the all repository-selection mode; an installation on selected repositories can't create repositories even when a workspace admin approved the scope. An existing installation holds the scope only after a workspace admin approves it through the installation URL.
+October 21, 2026
+Breaking. List Commits returns InvalidArgument (HTTP 400) for a path that contains a .. segment, where it used to list no commits. It also drops empty and . segments from path, so ./src//app.ts lists the commits that change src/app.ts instead of none. Migration: resolve .. segments before you send path, for example send src/app.ts instead of src/lib/../app.ts.
+Changed. List Namespaces also returns the namespaces where a grant on the namespace or one of its repositories names you or a group you belong to. It used to leave them out, even when List Repos could list repositories there. This extends the candidates named in the September 24 entry, and you still hold namespace:repositories:read on every namespace it returns.
+October 20, 2026
+Added. The pull_request.reviewer.added, pull_request.reviewer.removed, and pull_request.reviewer.rerequested webhook events are delivered when the reviewer is a service account, such as a bot that CODEOWNERS requests, where Origin used to send none of them. In the reviewer payload, reviewer carries a new serviceAccount object with the account's id and, when Cursor can describe the account, a type naming the product it acts for and a displayName. Origin might add more reviewer kinds, so ignore unknown fields when you decode reviewer, and treat a reviewer with no variant you recognize as unknown rather than as an error.
+Changed. Request Pull Request Reviewers and Remove Pull Request Requested Reviewers resolve reviewers for an installation access token against the members of the team that owns the repository's namespace and the members and groups of the organizations linked to that team. An installation token used to have no reviewer candidates on such a repository, so Request Pull Request Reviewers returned InvalidArgument (HTTP 400) for every reviewer it named. Installation user tokens and Cursor user credentials resolve candidates as before.
+October 19, 2026
+Added. List Commits accepts an optional path query parameter that lists only the commits that change a file or directory, without following renames. A merge is listed when the path differs from any of its parents, as git log --full-history -- <path> does. A directory matches when anything beneath it changes, and a commit must also match every email and time filter that's set. The page token carries the path, so path is ignored on a request that sends a token.
+Added. List Pull Requests accepts a repeatable mergeCommitShas query parameter that returns the pull requests whose mergeCommitSha equals any listed SHA. Each value must be a full 40- or 64-character commit SHA, and more than 100 distinct SHAs, or any value that isn't a full SHA, returns an empty list. Pass state=merged or state=all, because state defaults to open and a pull request has no merge commit until it merges.
+Added. List Pull Requests accepts optional mergedSince and mergedUntil query parameters, inclusive RFC 3339 bounds on mergedAt such as 2026-08-01T00:00:00Z. Unmerged pull requests never match, so pass state=merged or state=all, and a pull request must also match any since and until creation-time bounds that are set. A malformed timestamp returns InvalidArgument (HTTP 400).
+October 17, 2026
+Breaking. Ruleset bypass actors and the requiredReviewers of pull_request rules no longer carry a team object with organizationPublicId and groupPublicId. They name a Cursor organization group with group instead, whose group.id is the group's public ID (grp_…), and Origin derives the group's organization from that ID. List Rulesets, Get Ruleset, Create Ruleset, and Update Ruleset return group, and Create Ruleset and Update Ruleset return InvalidArgument (HTTP 400) for an entry that still sends team. This replaces the team shape in the October 14 and October 16 entries. Migration: send group.id with the value your integration sent as team.groupPublicId, drop team.organizationPublicId, and read group.id wherever you read team.groupPublicId.
+October 16, 2026
+Breaking. Ruleset bypass actors no longer have an originRole kind. Create Ruleset and Update Ruleset return InvalidArgument (HTTP 400) for a bypassActors[] entry that names an Origin role, and List Rulesets, Get Ruleset, and the create and update responses leave out any role actor a ruleset already stores. A role actor never granted a bypass: Origin doesn't resolve who holds a role when it evaluates a ruleset. Migration: replace each bypassActors[].originRole entry with user, team, or app entries that name the principals who can bypass the ruleset.
+Added. The repository.label.created, repository.label.updated, and repository.label.deleted webhook events report label definitions being created, updated, and deleted in a repository, including labels that createMissing creates on Set Pull Request Labels and Add Pull Request Labels. Created and deleted labels carry the label payload, and the updated payload adds previousLabel, the label as it was before the update. An update that changes nothing delivers nothing, and none of the three events is delivered for a repository Origin mirrors from GitHub. They require repository:labels:read.
+Changed. Create Ruleset and Update Ruleset return InvalidArgument (HTTP 400) for a name longer than 120 characters, where the request used to fail with an internal error (HTTP 500). The limit applies after trimming whitespace and counts UTF-16 code units, so an astral character such as an emoji counts twice.
+October 15, 2026
+Breaking. Add Pull Request Comment Reaction and Remove Pull Request Comment Reaction reject an emoji that contains @, which both endpoints used to accept. Migration: send reaction emoji without @.
+Changed. Merge Pull Request returns FailedPrecondition (HTTP 400), and nothing merges, when a merge commit is the only method that can land on the base branch and an active required_linear_history rule covers that branch, unless the caller can bypass every ruleset that holds such a rule. A squash can't land when the repository's allowSquashMerge is false or a pull_request rule's allowedMergeMethods leaves it out. Get Pull Request Mergeability reports the condition as a ruleset_error blocker. Such a pull request used to read as mergeable when nothing else blocked it, and the merge failed when Origin pushed the merge commit.
+October 14, 2026
+Breaking. The pull_request.base_ref.updated webhook event is delivered only when a pull request is retargeted onto a different base branch. Origin used to also deliver it when the pull request's resolved base commit changed without a retarget, as when a head push found that the base branch had advanced. Migration: read the base commit from pullRequest.version.baseSha on pull_request.head_ref.pushed, which every head push still delivers.
+Breaking. Merge Pull Request returns FailedPrecondition (HTTP 400), and nothing merges, when the pull request's base branch is the head branch of a pull request that has already merged. For a stack, the base that counts is the one the merge lands on. Such a merge used to land on a branch whose commits never reach the branch the earlier pull request merged into. The repository's default branch is exempt, as is a base branch that an active push_branch ruleset with a deletion rule names in includedRefNames. Get Pull Request Mergeability reports the condition as a needs_restack blocker. Migration: set the pull request's base to the branch the error message names with Update Pull Request, then merge it.
+Breaking. Create Ruleset and Update Ruleset return InvalidArgument (HTTP 400) for a bypassActors[].team entry unless its group exists, belongs to the organization team.organizationPublicId names, and that organization is linked to the team that owns the repository's namespace. A repository whose namespace no team owns accepts no team entry. Such entries used to be stored. Migration: name a group of an organization linked to the repository's owning team in team.organizationPublicId and team.groupPublicId, or remove the team entry.
+Added. The pull_request.unpublished webhook event reports an open pull request becoming a draft again. It carries the same payload as pull_request.published and requires repository:pull_requests:read.
+Added. pull_request.base_ref.updated payloads include previousBase, the base ref and sha the pull request had before it was retargeted. The other pull request events omit it.
+Added. Push rulesets accept the max_file_size rule type, which rejects a push that introduces a file larger than its maxFileSizeBytes parameter, from 1 to 104857600 (100 MiB). The whole push is rejected, and files the repository already stores aren't judged again. Because the rule covers a whole push, only a push_repository ruleset accepts it. Set it with Create Ruleset or Update Ruleset.
+Added. pull_request rules accept requiredReviewers, teams whose members must approve a pull request. Each entry names a Cursor group by team.organizationPublicId and team.groupPublicId and sets minimumApprovals, from 1 to 50, defaulting to 1. Only approvals from the group's members count toward it, and a listed team that later stops resolving blocks every merge the rule covers. Set it with Create Ruleset or Update Ruleset, which return InvalidArgument (HTTP 400) when the save adds a team the repository can't require.
 October 13, 2026
 Added. Enable Pull Request Auto Merge turns on auto-merge, so Origin merges a pull request on the caller's behalf once it's mergeable, and a stacked pull request once it's also the lowest open one in its stack: PUT /v1/origin/repos/{ownerSlug}/{repoName}/pulls/{pullNumber}/auto_merge. The optional body sets the mergeMethod, under the same rules as Merge Pull Request, and the merge commit's commitTitle and commitMessage. Calling it while auto-merge is on re-arms it for the caller with that call's options, and a closed or merged pull request returns FailedPrecondition (HTTP 400). Requires repository:contents:write, isn't available to installation user tokens, and costs 5 points. The endpoint is in preview.
 Added. Disable Pull Request Auto Merge turns auto-merge off, and succeeds when it isn't on: DELETE /v1/origin/repos/{ownerSlug}/{repoName}/pulls/{pullNumber}/auto_merge. Requires repository:pull_requests:write and costs 5 points. The endpoint is in preview.
