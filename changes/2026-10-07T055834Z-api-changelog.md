 Origin API Changelog
 The Origin API is in Early Beta and subject to change. Review the OpenAPI specification when updating an integration.
 Changes to the Origin public API, including endpoints, request and response schemas, scopes, and webhooks, grouped by day with the newest first. Each change carries one label: Breaking, Deprecated, Added, Changed, or Removed. Breaking and deprecated changes include migration guidance inline. The Origin API reference always reflects the latest synced state.
+October 6, 2026
+Breaking. A user actor's email is an empty string in pull request, review, comment, check run, requested reviewer, and merge eligibility responses, such as author.user.email on Get Pull Request, unless the caller holds repository:members:read on the repository. List Pull Requests rejects an email author filter from such a caller with PermissionDenied (HTTP 403). Webhook payloads still carry emails. Installations that held repository:metadata:read when Origin split out repository:members:read on October 3 already hold it. Migration: request repository:members:read to read user emails and filter by author email, or filter List Pull Requests by the author's user_… ID.
+Breaking. Get Repo returns mirror only to a caller holding repository:mirror:read on the repository and omits it otherwise, as it does for a native repository. Installations and apps' default scopes don't include that scope, so an installation reads mirror from Get Repo only after a workspace admin approves repository:mirror:read for it. Migration: request repository:mirror:read to keep reading mirror from Get Repo.
+Breaking. An actor field that names a deleted user or service account is absent from responses and webhook payloads. A deleted service account used to appear with its id alone, and a deleted user made reads that include their pull requests, reviews, or comments, such as List Pull Requests, fail with an internal error (HTTP 500). Requested-reviewer lists leave out a deleted reviewer, and Origin doesn't send pull_request.reviewer.added, pull_request.reviewer.removed, or pull_request.reviewer.rerequested for one. App actors are unchanged, and a deleted service account in performedVia still appears with its id. Migration: treat an absent actor field, such as a pull request's author, as an account that no longer exists, instead of reading a service account id from it.
+Breaking. Origin deletes a pull request's merge preview at refs/pull/{pullNumber}/merge when the pull request closes or merges, so Get Git Ref returns 404 for it afterward instead of the last preview. Reopening the pull request prepares a new one. Migration: read a merged pull request's mergeCommitSha instead of its merge preview, and treat a 404 for a closed pull request's preview as expected.
+Added. Merge-conflict blockers from Get Pull Request Mergeability carry conflictsBeyondDownstack, true when the pull request conflicts on a path the pull request below it in the stack doesn't. It's false when every conflict is inherited from below, and true when the pull request isn't in a stack. Read it with inheritedFromDownstack, which can be true while the pull request also conflicts on its own paths. The endpoint is in preview.
+Changed. repository.pushed payloads carry a pusher that is a since-deleted app with its id alone, where they used to omit pusher, so the push looked like one Origin performed itself. pusher is absent for Origin's own pushes and when Origin couldn't resolve the pusher as it recorded the event, such as a user whose account no longer exists.
+Changed. Create Label and Update Label return InvalidArgument (HTTP 400) for a name or description that contains a NUL character, where the request used to fail with an internal error (HTTP 500).
+October 3, 2026
+Breaking. Get Repository Collaborator Permission requires repository:members:read instead of repository:metadata:read, Sync Mirror requires repository:mirror:sync instead of repository:contents:read, and Get Mirror Transition Job and Get Active Mirror Transition Job require repository:mirror:read instead of repository:metadata:read. Origin granted each new scope wherever the scope it was split from was already granted, except that installations and apps' default scopes didn't receive repository:mirror:sync or repository:mirror:read. Existing integrations keep access to Get Repository Collaborator Permission, and an app can call Sync Mirror once a workspace admin approves repository:mirror:sync for its installation. Migration: request repository:members:read instead of relying on repository:metadata:read to call Get Repository Collaborator Permission, and request repository:mirror:sync alongside repository:contents:read to call Sync Mirror.
+Breaking. Create Ruleset and Update Ruleset reject a bypassActors[].user.id that isn't a public user ID (user_…) with InvalidArgument (HTTP 400), including the numeric Cursor user ID they still accepted after the October 2 move to public IDs. Migration: send the user_… ID that actor payloads and ruleset reads return in bypassActors[].user.id, in place of the numeric Cursor user ID.
+Breaking. Update Pull Request returns FailedPrecondition (HTTP 400) when it reopens a closed pull request whose base branch no longer exists, even when the same request also sets base, and the pull request stays closed. Origin used to reopen it onto the missing branch. Migration: restore or push the base branch before you reopen the pull request, then send base in a later request if it should merge into another branch.
+Breaking. Detach Repo Mirror waits up to 2 minutes for an inbound repository's last fetch from GitHub before it detaches, so a fetch already underway can't overwrite pushes made after the detach; it used to detach at once. If that fetch fails or Origin can't resolve the repository's GitHub remote, the request returns FailedPrecondition (HTTP 400), and other failures, such as a timeout, return an error such as Unavailable (HTTP 503) or DeadlineExceeded (HTTP 408). In each case the repository stays mirrored. Migration: allow up to 2 minutes for Detach Repo Mirror on an inbound repository, and when it fails, fix the cause it names and retry.
+Added. Prepare Pull Request Merge Ref brings a pull request's test merge at refs/pull/{pullNumber}/merge up to date with the current tip of its base branch, which Origin doesn't do on its own when only the base moves: POST /v1/origin/repos/{ownerSlug}/{repoName}/pulls/{pullNumber}/merge_ref. It returns a state of mergeable with the refreshed mergeCommitSha, conflicted, or pending, which means call again, and accepts an optional expectedHeadSha that rejects the call if the head moved. The endpoint is in preview, requires repository:pull_requests:read, and costs 10 points.
+Added. Service account actors carry type, the product the account acts for (bugbot, automations, agent_serve, agent, grok_bot, or env_builds), and displayName, the name Cursor shows for it, such as Cursor for Cursor's own accounts or a Grok bot's name. type is absent when the account no longer exists or Cursor can't describe it, and displayName when the account has no product name. Both appear wherever a response or webhook payload carries a serviceAccount actor, including performedVia.serviceAccount, such as author.serviceAccount on Get Pull Request and actor.serviceAccount on Get Check Run. See Resource references.
+October 2, 2026
+Breaking. List Rulesets, Get Ruleset, Create Ruleset, and Update Ruleset return bypassActors[].user.id as the user's public ID (user_…), where they used to return the numeric Cursor user ID encoded as a decimal string. Create Ruleset and Update Ruleset accept the public ID in bypassActors[].user.id. Migration: read and store bypassActors[].user.id as a user_… ID, and send user_… IDs when you create or update a ruleset.
+Breaking. Dismiss Pull Request Review also requires repository:contents:write to dismiss another reviewer's request_changes review, because a change request can block merge; without it, the request returns PermissionDenied (HTTP 403). Migration: add repository:contents:write alongside repository:pull_requests:reviews:write to the scopes your app requests if it dismisses request_changes reviews it didn't submit.
+Added. Add Pull Request Comment Reaction adds the caller's reaction to a pull request comment: POST /v1/origin/repos/{ownerSlug}/{repoName}/pulls/comments/{commentId}/reactions. The body's emoji can be any emoji of up to 32 Unicode code points and is stored exactly as sent. Adding a reaction the caller already holds succeeds without change, and with an installation access token the reactor is the installation's app. Requires repository:pull_requests:reviews:write and costs 5 points.
+Added. Remove Pull Request Comment Reaction removes the caller's reaction, named by its percent-encoded emoji: DELETE /v1/origin/repos/{ownerSlug}/{repoName}/pulls/comments/{commentId}/reactions/{emoji}. Removing a reaction the caller doesn't hold succeeds without change, and other principals' reactions are never affected. Requires repository:pull_requests:reviews:write and costs 5 points.
+Added. Pull request comments carry reactions, every reaction on the comment, oldest first, each with its emoji, content, and reactor. Returned by List Pull Request Comments, Get Pull Request Comment, Create Pull Request Comment, and Update Pull Request Comment, and carried, empty, by the pull_request.comment.created payload. The reaction in the reaction payloads also carries emoji.
+Added. Repository, pull request, and commit responses carry webUrl, the resource's web URL on Cursor, absent when Origin can't form a link. Returned for repositories by List Repos, Get Repo, Create Repo, Update Repo, List App Installation Repositories, and Transition Repo Mirror; for pull requests by List Pull Requests, Get Pull Request, Create Pull Request, Update Pull Request, and Merge Pull Request; and for commits by Get Commit, List Commits, List Pull Request Commits, and Compare Commits. The repository.created and repository.metadata.updated payloads and the pull_request.* lifecycle payloads carry it too.
+Added. User actors in responses and webhook payloads can carry performedVia.serviceAccount, naming the service account the user acted through, such as their personal Grok bot. As with performedVia.app, the user is still the actor. See Resource references.
+Changed. pull_request.comment.reaction.added is delivered only when the reaction is new: re-placing a reaction the reactor already holds delivers nothing, where it used to deliver the event again.
+Changed. A comment reaction can be any emoji, so a reaction's content carries CONTENT_UNSPECIFIED for an emoji outside the eight that have a name, where every reaction used to have one of those names. Read emoji instead. Carried by the reaction payloads and returned in reactions[].content on pull request comment responses.
 October 1, 2026
 Added. Replace Inbound IP Allowlist Entries replaces a namespace's allowlist entries with a complete set in one call: POST /v1/origin/namespaces/{namespaceSlug}/inbound-ip-allowlist/entries:replace. The body takes entries[], up to 1,000, each with a required cidr and optional description and enabled. Entries are matched by cidr as typed after trimming, with no normalization: a matched entry keeps its id, a new CIDR is added, and an omitted one is deleted. The call doesn't change whether the list is enforced. An optional etag rejects the call with Aborted (HTTP 409 Conflict) if the entries changed since that read, and an empty entries requires allowEmpty. The response carries the allowlist plus addedCount, updatedCount, removedCount, and unchangedCount. Requires a Cursor user credential holding namespace:settings:write and costs 10 points per call.
 Added. Get Inbound IP Allowlist and Update Inbound IP Allowlist responses carry etag, a version of the entry set that changes whenever an entry is added, updated, or removed.
