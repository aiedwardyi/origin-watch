 Origin API Changelog
 The Origin API is in Early Beta and subject to change. Review the OpenAPI specification when updating an integration.
 Changes to the Origin public API, including endpoints, request and response schemas, scopes, and webhooks, grouped by day with the newest first. Each change carries one label: Breaking, Deprecated, Added, Changed, or Removed. Breaking and deprecated changes include migration guidance inline. The Origin API reference always reflects the latest synced state.
+September 25, 2026
+Breaking. Comment thread and review version references no longer carry createdAt; they hold only the version's number, headSha, and baseSha. This covers thread.version on List Pull Request Comments, Get Pull Request Comment, Create Pull Request Comment, and Update Pull Request Comment, version on Update Pull Request Thread, pullRequestVersion on List Pull Request Reviews, Create Pull Request Review, Update Pull Request Review, and Dismiss Pull Request Review, and the same fields in the pull_request.comment.created and pull_request.review.* payloads. Migration: wherever your integration read createdAt from a thread or review version, read it from version on Get Pull Request or on the pull_request.* lifecycle payload that recorded that version, matching on number.
+Added. Pull request versions carry potentialMergeCommit, Origin's test merge of that version: state is prepared, merge_conflict, or unknown, and a prepared merge adds the merge commit's sha and the base branch tip baseSha it was built on. Returned in version by List Pull Requests, Get Pull Request, Create Pull Request, Update Pull Request, and Merge Pull Request, and carried by the pull_request.* lifecycle payloads, so a webhook receiver learns the merge preview without calling Get Git Ref. An event carries the value as of its emission, so treat unknown as not yet known and re-read the pull request.
+Added. Create Installation User Token mints an installation user token that acts on behalf of an eligible namespace member: POST /v1/origin/app/installations/{installationId}/user_access_tokens. Requires an app JWT and an installation granted namespace:user_tokens:write. Name the user with userId or userEmail; optional scopes and repositoryIds narrow access. The token expires within 15 minutes and never outlives the app JWT.
+Added. User actors can include performedVia.app with the app's id and optional displayName when an app acted on the user's behalf. The field is absent for direct user actions and can be absent when delegation data is unavailable. See Acting on behalf of users.
+Added. List Commits accepts authorEmails and committerEmails filters, with up to 100 distinct emails each. Matching ignores case and surrounding whitespace; a commit must match both lists when both are set. A filtered page can be empty and still have a nextPageToken, so keep paging until the token is empty.
+Changed. A cancelled check run no longer displaces a passing result. A completed post with the conclusion cancelled to a run that is completed with success, neutral, or skipped is ignored as stale whatever its externalUpdatedAt, so Post Check Run and Batch Upsert Check Runs answer 200 with the stored run and the outcome ignored_stale. A cancellation posted as a new run attempt or suite attempt ranks below the passing attempt instead, so List Check Runs For Commit, List Check Suites For Commit, List Check Runs For Suite, and Get Pull Request Mergeability keep reporting the pass. A newer failure still replaces a pass, and a cancellation still applies over a failing or pending run; Attempts and the current attempt has the full rule.
 September 24, 2026
 Added. List Namespaces lists the namespaces you can list repositories in, ordered by slug: GET /v1/origin/namespaces. The candidates are your teams' namespaces, your personal namespace, and the namespaces holding repositories you were granted, and only those on which you hold namespace:repositories:read are returned, so each namespace.slug is a valid ownerSlug for List Repos. Each entry's viewerCanCreateRepositories says whether Create Repo in that namespace would pass authorization and the owner's plan and settings checks for you. Pages hold 30 namespaces by default and at most 100. Requires a Cursor user credential and no scope, and costs 1 point; app tokens, installation tokens, and service accounts receive PermissionDenied (HTTP 403).
-Added. Repository visibility has a third allowed value, public, beside internal and private. The value belongs to the repository schema that List Repos, Get Repo, Create Repo, Update Repo, List App Installation Repositories, Transition Repo Mirror, and Force Repo Mirror Cutover return and that the repository.created and repository.metadata.updated payloads carry. Update Repo rejects a request that sets visibility to public with FailedPrecondition (HTTP 400), so no repository can be made public through the API. Treat public as a valid value wherever your integration reads visibility.
 September 23, 2026
 Changed. Reopening a pull request through Update Pull Request records a new version when the head moved while the pull request was closed, and sends pull_request.head_ref.pushed. The pull request previously kept the head it had when it was closed until the branch was pushed again. The recorded version carries its own headSha, baseSha, and diff stats, the same shape a push records. Merged pull requests are unaffected.
 Changed. An abbreviated commit SHA sent to Get Commit or List Commit Files resolves the same way as on Get Git Commit: among commit objects only, so a prefix that names exactly one commit resolves even when a blob or tree in the repository shares it. The September 22 entry named Get Git Commit only. Get Blob and Get Tag are unchanged.
