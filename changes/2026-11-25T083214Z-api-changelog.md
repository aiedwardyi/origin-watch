 Origin API Changelog
 The Origin API is in Early Beta and subject to change. Review the OpenAPI specification when updating an integration.
 Changes to the Origin public API, including endpoints, request and response schemas, scopes, and webhooks, grouped by day with the newest first. Each change carries one label: Breaking, Deprecated, Added, Changed, or Removed. Breaking and deprecated changes include migration guidance inline. The Origin API reference always reflects the latest synced state.
+November 23, 2026
+Breaking. Create Pull Request Review rejects a bot service account's approve of a version that is no longer the pull request's latest with FailedPrecondition (HTTP 400), and records nothing. Such an approval used to be recorded. The bot's comment and request_changes reviews are still accepted on any version. Migration: have the bot review the pull request's latest version and approve that version.
+November 22, 2026
+Changed. The Get Blob description states that Origin rejects a blob larger than 4 MiB (decoded) with FailedPrecondition (HTTP 400), which is how it already answered those requests. It used to say only that such blobs are rejected.
+November 19, 2026
+Changed. Create Git Ref returns InvalidArgument (HTTP 400) for a branch name longer than 4,000 bytes in UTF-8. Such a request used to fail with an internal error.
+Changed. Visible comments and replies, submitted reviews, review requests added or removed, and labels added or removed move a pull request's updatedAt forward, so sortBy=updated on List Pull Requests orders by that activity. They used to leave updatedAt unchanged.
+Changed. When Origin can't read a team's inbound IP allowlist, it keeps applying the last copy it read for up to ten minutes, then refuses the requests that list checks with PermissionDenied (HTTP 403). Those requests used to be admitted while the list couldn't be read.
 November 18, 2026
 Breaking. Create Ruleset and Update Ruleset reject a push_repository ruleset whose includedRefNames or excludedRefNames holds a pattern, ~ALL included, with InvalidArgument (HTTP 400), unless the ruleset already is a push_repository ruleset that stores that pattern in the same list. A push_repository ruleset applies to every push whatever its patterns, so these requests used to succeed and store patterns that limited nothing. Migration: send empty includedRefNames and excludedRefNames for a push_repository ruleset, or use a push_branch or push_tag ruleset to protect only some branches or tags.
+Breaking. Create Ruleset and Update Ruleset reject an includedRefNames or excludedRefNames list whose brace groups and ranges, such as {main,dev} and {1..9}, expand it to more than 1,024 patterns, with InvalidArgument (HTTP 400). Update Ruleset still accepts a list sent exactly as the ruleset already stores it. Such lists used to be accepted at any size. Migration: use fewer {a,b} alternatives and {1..9} ranges in each list, or name the branches or tags with one pattern each.
 Added. List Installation User Repositories lists the repositories an installation user token can read: GET /v1/origin/user/installations/{installationId}/repos. A repository is listed when the acting user can read it, the installation can read it, and the token's repositoryIds, when set, include it. Only an installation user token minted for that installation can call it, and it requires repository:metadata:read.
 Added. Update Repo accepts an optional name in its request body that renames the repository within its owner. The previous name keeps resolving to the repository for Git and API requests, web links to it redirect to the new name, and no other repository can take it. A rename delivers repository.renamed, needs the same repository:settings:write scope as the rest of Update Repo, and works only on repositories whose source of truth is Origin.
 Changed. The x-origin-scopes extension in the OpenAPI specification lists a fourth tokenTypes value, installation_as_user, on every operation that accepts an installation user token, and the reference shows it as an Installation user token Auth badge. Authorization is unchanged; the extension publishes which operations already accepted installation user tokens.
