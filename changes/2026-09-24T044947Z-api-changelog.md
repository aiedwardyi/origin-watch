+Apps and installations
+Changed. Create Installation Access Token states that a token expires after at most 15 minutes and never later than the app JWT that requested it. Read expiresAt on the response and mint a new token when it passes rather than assuming a duration.
 Pull requests
 Breaking. Create Pull Request no longer accepts parentPullNumber. A request that carries it returns InvalidArgument (HTTP 400) naming parent_pull_number rather than creating the pull request, so a client that kept sending it fails loudly instead of silently losing the stack parent. Migration: send parentPullRequest with a number member wherever your integration sent parentPullNumber.
 Added. Delete Pull Request Comment deletes a pull request comment by its Origin id: DELETE /v1/origin/repos/{ownerSlug}/{repoName}/pulls/comments/{commentId}. The comment's author can always delete it, and any other caller must hold write access to the repository through repository:contents:write or receives PermissionDenied (HTTP 403). Deleting the last comment of a thread removes the thread, deleting any other comment leaves the thread in place, and the comment's reactions and edit history go with it. An unknown or already-deleted id returns 404. Requires repository:pull_requests:reviews:write and costs 5 points.

+Git data
+Changed. Get Git Commit resolves an abbreviated sha only when it has at least 5 hex characters, and only among commit objects; the request fails when no commit or more than one commit carries the abbreviation. Full SHAs, branches, tags, and HEAD resolve as before.
+SSH certificate authorities
+Added. List SSH Certificate Authorities lists the SSH certificate authorities an owner trusts for git over SSH, newest first, together with requireCertificates, whether the owner requires certificates: GET /v1/origin/owners/{ownerSlug}/ssh-certificate-authorities. The response is not paginated, and each certificateAuthorities[] entry carries id, name, keyType, fingerprint, publicKey, and createdAt. Requires namespace:settings:read.
+Added. Add SSH Certificate Authority adds an authority the owner trusts and returns it: POST /v1/origin/owners/{ownerSlug}/ssh-certificate-authorities. The body takes a required publicKey, one OpenSSH authorized_keys line whose key type is ssh-ed25519, ecdsa-sha2-nistp256, ecdsa-sha2-nistp384, ecdsa-sha2-nistp521, or ssh-rsa with a modulus of at least 2048 bits, and a required name of at most 255 characters. A certificate, an unsupported key type, or a shorter RSA key returns InvalidArgument (HTTP 400); a key the owner already lists returns AlreadyExists (HTTP 409 Conflict), with the check scoped to the owner rather than to Origin as a whole; and an owner that is not team-owned returns FailedPrecondition (HTTP 400). Requires a Cursor user credential holding namespace:settings:write.
+Added. Delete SSH Certificate Authority removes an authority from the owner and answers 204 No Content: DELETE /v1/origin/owners/{ownerSlug}/ssh-certificate-authorities/{certificateAuthorityId}. Every certificate the authority signed stops working, and while the owner requires certificates its last authority cannot be removed, which returns FailedPrecondition (HTTP 400). Requires a Cursor user credential holding namespace:settings:write.
+Added. Set SSH Certificate Requirement sets whether the owner requires SSH certificates: POST /v1/origin/owners/{ownerSlug}/ssh-certificate-authorities:setRequirement. The body takes a required requireCertificates boolean, and the response carries the owner's requireCertificates setting. While required, git over SSH on the owner's repositories accepts only certificates from the owner's authorities, so SSH keys registered by users and user API keys over HTTPS are refused. Requiring certificates with no listed authority returns FailedPrecondition (HTTP 400), and setting the current value succeeds without change. Requires a Cursor user credential holding namespace:settings:write.
 Webhooks
 Added. pull_request.comment.reaction.added and pull_request.comment.reaction.removed are subscribable webhook events, delivered when a reaction is placed on or removed from a pull request comment. Their shared payload carries the pullRequest reference, a comment reference with its thread, and the reaction with its content and reactor. An add is delivered at least once: re-placing a reaction the reactor already holds delivers the event again for the same comment, reactor, and content, so fold on that triple. Removing a reaction the reactor does not hold delivers nothing.
+Changed. The pull_request.label.removed payload carries actor, the principal that removed the label, when known. The September 19 entry described actor as set on pull_request.label.added only; it is set on both events when the principal is known.
 September 19, 2026
 Added. Delete Git Ref deletes a branch reference: DELETE /v1/origin/repos/{ownerSlug}/{repoName}/git/refs/{ref}. The path names the branch as refs/heads/<branch> or heads/<branch>, and only branch references can be deleted. A branch that does not exist returns 404; the repository default branch, a branch a deletion rule protects, and a repository whose contents are mirrored from another host each return FailedPrecondition (HTTP 400); and a branch whose tip moves while the delete is in flight returns FailedPrecondition (HTTP 400) or Aborted (HTTP 409 Conflict), so retry to delete the new tip. Pull requests whose head is the deleted branch are closed, as after a pushed deletion. Requires repository:contents:write and costs 5 points.
 Added. pull_request.label.added and pull_request.label.removed are subscribable webhook events, delivered when a label is assigned to or unassigned from a pull request. Their shared payload carries the pullRequest reference and the label snapshot, plus an actor naming the principal that assigned the label on pull_request.label.added only. Deleting a label definition delivers one pull_request.label.removed for every pull request that carried the label.
