 Origin API Changelog
 The Origin API is in Early Beta and subject to change. Review the OpenAPI specification when updating an integration.
 Changes to the Origin public API, including endpoints, request and response schemas, scopes, and webhooks, grouped by day with the newest first. Each change carries one label: Breaking, Deprecated, Added, Changed, or Removed. Breaking and deprecated changes include migration guidance inline. The Origin API reference always reflects the latest synced state.
+October 13, 2026
+Added. Enable Pull Request Auto Merge turns on auto-merge, so Origin merges a pull request on the caller's behalf once it's mergeable, and a stacked pull request once it's also the lowest open one in its stack: PUT /v1/origin/repos/{ownerSlug}/{repoName}/pulls/{pullNumber}/auto_merge. The optional body sets the mergeMethod, under the same rules as Merge Pull Request, and the merge commit's commitTitle and commitMessage. Calling it while auto-merge is on re-arms it for the caller with that call's options, and a closed or merged pull request returns FailedPrecondition (HTTP 400). Requires repository:contents:write, isn't available to installation user tokens, and costs 5 points. The endpoint is in preview.
+Added. Disable Pull Request Auto Merge turns auto-merge off, and succeeds when it isn't on: DELETE /v1/origin/repos/{ownerSlug}/{repoName}/pulls/{pullNumber}/auto_merge. Requires repository:pull_requests:write and costs 5 points. The endpoint is in preview.
+Added. Pull requests carry autoMerge while auto-merge is on: who turned it on and when, in enabledBy and enabledAt, the mergeMethod it lands with, and any commitTitle and commitMessage it was given. Returned by List Pull Requests, Get Pull Request, Update Pull Request, and Enable Pull Request Auto Merge. The field is in preview.
+Added. The pull_request.merge_when_ready.enabled and pull_request.merge_when_ready.disabled webhook events report auto-merge turning on, and turning off without a merge; a merge that auto-merge lands delivers pull_request.merged. The disabled payload carries the disabledReason, such as manual, merge_failed, or pull_request_closed, and disabledBy when a principal turned it off. Both events require repository:pull_requests:read and are in preview.
+Added. Add Pull Request Labels and Set Pull Request Labels accept createMissing. When it's true, a name with no exact match reuses the one label that matches it ignoring case, or else creates a label with color ededed, and the response's createdLabels lists the labels the request created. Setting it requires repository:labels:write in addition to repository:pull_requests:write, and each label created costs 5 more points.
+Added. pull_request rules accept allowedMergeMethods, the merge methods a pull request can land with on a targeted branch: merge, squash, or both. Set it with Create Ruleset or Update Ruleset. While an active rule sets it, Merge Pull Request returns FailedPrecondition (HTTP 400) for any other mergeMethod, and a merge that doesn't name a method lands with an allowed one.
+Changed. A 429 rate limit response sends Retry-After as the seconds left in the window plus one, from 2 to 60, where it always sent 60. It's still 60 when Origin can't read the window, and X-RateLimit-Reset still advertises a full 60-second window.
+Changed. When Add Pull Request Labels or Set Pull Request Labels names labels that don't exist, the NotFound (HTTP 404) error lists every unknown name, where it used to name only the first.
 October 12, 2026
 Breaking. In a repository that allows merge commits, Merge Pull Request returns FailedPrecondition (HTTP 400) with every mergeMethod, and nothing merges, when the pull request's version.baseSha, as Get Pull Request returns it, has diverged from its base branch. A pull request is left that way when its parent is squash-merged and it's retargeted onto the branch the parent landed on. For a stack, Origin checks the lowest unmerged pull request. Such a merge used to land against Git's merge base, which might bring back changes the pull request removed. Get Pull Request Mergeability reports the condition as a needs_restack blocker. Migration: rebase the pull request's own commits onto its base branch and push them before you call Merge Pull Request.
 Added. A user confirmation link can name your app with client_id instead of one installation with installation_id. Origin resolves it to the app's active installations in the namespaces the user belongs to: one continues as that installation's link, several let the user pick a namespace, and none shows that the app isn't installed in any namespace the user belongs to. A link that carries both parameters uses installation_id, and its client_id must be the app the installation belongs to. The confirmation receipt's installation_id and namespace_id name the installation the user chose.
