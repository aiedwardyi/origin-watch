 Origin API Changelog
 The Origin API is in Early Beta and subject to change. Review the OpenAPI specification when updating an integration.
 Changes to the Origin public API, including endpoints, request and response schemas, scopes, and webhooks, grouped by day with the newest first. Each change carries one label: Breaking, Deprecated, Added, Changed, or Removed. Breaking and deprecated changes include migration guidance inline. The Origin API reference always reflects the latest synced state.
+November 18, 2026
+Breaking. Create Ruleset and Update Ruleset reject a push_repository ruleset whose includedRefNames or excludedRefNames holds a pattern, ~ALL included, with InvalidArgument (HTTP 400), unless the ruleset already is a push_repository ruleset that stores that pattern in the same list. A push_repository ruleset applies to every push whatever its patterns, so these requests used to succeed and store patterns that limited nothing. Migration: send empty includedRefNames and excludedRefNames for a push_repository ruleset, or use a push_branch or push_tag ruleset to protect only some branches or tags.
+Added. List Installation User Repositories lists the repositories an installation user token can read: GET /v1/origin/user/installations/{installationId}/repos. A repository is listed when the acting user can read it, the installation can read it, and the token's repositoryIds, when set, include it. Only an installation user token minted for that installation can call it, and it requires repository:metadata:read.
+Added. Update Repo accepts an optional name in its request body that renames the repository within its owner. The previous name keeps resolving to the repository for Git and API requests, web links to it redirect to the new name, and no other repository can take it. A rename delivers repository.renamed, needs the same repository:settings:write scope as the rest of Update Repo, and works only on repositories whose source of truth is Origin.
+Changed. The x-origin-scopes extension in the OpenAPI specification lists a fourth tokenTypes value, installation_as_user, on every operation that accepts an installation user token, and the reference shows it as an Installation user token Auth badge. Authorization is unchanged; the extension publishes which operations already accepted installation user tokens.
+Changed. The nextPageToken that List Commits returns carries the full SHA that sha resolved to on the first page, so requests that pass it as pageToken keep walking from that commit even when the branch or tag moves between pages. The token used to carry the ref name, so a push between pages could repeat commits already listed, and a force-push could skip commits.
+Changed. Update Ruleset leaves a ruleset as it is when the request matches what the ruleset already stores, and returns it with each rule's and bypass actor's id unchanged. Such a request used to rewrite the ruleset and assign new IDs to its rules and bypass actors.
+Changed. Update Repo accepts deleteBranchOnMerge on a repository that pulls from an upstream source. The value is stored and takes effect once Origin becomes the repository's source of truth, and a mirror transition doesn't change it. Such a request used to return FailedPrecondition (HTTP 400).
+Changed. The OpenAPI specification publishes the request limits Origin applies as schema keywords, maxItems, maxLength, maximum, and default, so client generators and validators can read them. For example, labels in the request body of Add Pull Request Labels carries maxItems: 100. The limits themselves didn't change. The pageSize descriptions on List Pull Requests, List Pull Request Comments, and List Pull Request Reviews also state that values above 100 are clamped to 100, which is how Origin already handled them.
+Changed. The repository.renamed payload description states that no other repository can take a renamed repository's previous name and that the renamed repository can rename back to it, which is how Origin already handled previous names. It used to say the previous name kept resolving only until another repository took it.
+November 17, 2026
+Changed. When a pull_request rule sets requireCodeOwnerReview through Create Ruleset or Update Ruleset, a changed path whose code owners resolve only to the pull request's author is satisfied by any approval that counts toward requiredApprovingReviewCount. Such a path used to block Merge Pull Request whatever approvals the pull request had, because the author can't approve their own pull request.
 November 14, 2026
 Changed. A group's review request clears only when a current member of the group who isn't the pull request's author submits an approve or request_changes review, so List Pull Request Requested Reviewers keeps returning the group after a comment review or a review by the author. Those reviews used to clear the group's request. A request for a user or service account still clears when that reviewer submits a review with any verdict.
