 Origin API Changelog
 The Origin API is in Early Beta and subject to change. Review the OpenAPI specification when updating an integration.
 Changes to the Origin public API, including endpoints, request and response schemas, scopes, and webhooks, grouped by day with the newest first. Each change carries one label: Breaking, Deprecated, Added, Changed, or Removed. Breaking and deprecated changes include migration guidance inline. The Origin API reference always reflects the latest synced state.
+November 4, 2026
+Added. The repository.renamed webhook event is delivered when a repository's name changes within its owner namespace, including a change of case only. Its payload carries the repository after the rename, previousName, the actor that renamed it when known, and renamedAt. Subscribing requires repository:metadata:read.
+Added. An inbound IP allowlist can trust the egress IP ranges that apps declare. Get Inbound IP Allowlist and Update Inbound IP Allowlist return trustAppDeclaredIps, and so does allowlist on Replace Inbound IP Allowlist Entries. Update Inbound IP Allowlist accepts an optional trustAppDeclaredIps in its request body to set it. While it's true, the list also admits an installation access token or an installation user token calling from an egress IP range its app declares. It doesn't change Get Repo Tarball.
+Changed. enabled is optional on Update Inbound IP Allowlist. A request must set enabled, trustAppDeclaredIps, or both; one that sets neither returns InvalidArgument (HTTP 400).
+Changed. Create Ruleset and Update Ruleset accept up to 50 rules and up to 100 bypassActors, up from 20 and 15.
+Changed. The inbound IP allowlist reference states which lists a request must pass: the list of the team that owns the repository or namespace it names, and the list of the requesting member's or service account's own team. Installation access tokens, installation user tokens, and service accounts are checked on every surface, not only at Get Repo Tarball. It also states that an enforced list covers MCP requests, that a refused API request, or one whose address Origin can't determine, returns PermissionDenied (HTTP 403), that requests from Cursor's own services aren't checked against the list, and that a change can take up to a minute to apply. Add Inbound IP Allowlist Entry documents that an entry that would make an enforced list exclude the caller's own address returns InvalidArgument (HTTP 400), and the error model documents that a 403 can mean an allowlist refused the request's address.
 October 28, 2026
 Breaking. A user's approval counts toward a pull_request rule's requiredApprovingReviewCount, requireCodeOwnerReview, and requiredReviewers only while the user has permission to submit reviews on the repository. Approvals from users without that permission, such as someone whose access was removed after they approved or a group member who can only read the repository, used to count and no longer do. Get Pull Request Mergeability can therefore report a pull request as blocked that it used to report as mergeable, and Merge Pull Request refuses it with FailedPrecondition (HTTP 400). Migration: request a new approval from someone with permission to submit reviews on the repository, or restore the approver's access.
 Added. Create Repo accepts an optional visibility in its request body, internal or private, and creates the repository with it. Omitting it creates an internal repository, which is what Create Repo created for every request before.
