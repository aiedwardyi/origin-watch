 Origin API Changelog
 The Origin API is in Early Beta and subject to change. Review the OpenAPI specification when updating an integration.
 Changes to the Origin public API, including endpoints, request and response schemas, scopes, and webhooks, grouped by day with the newest first. Each change carries one label: Breaking, Deprecated, Added, Changed, or Removed. Breaking and deprecated changes include migration guidance inline. The Origin API reference always reflects the latest synced state.
+September 22, 2026
+Pull requests
+Breaking. Create Pull Request no longer accepts parentPullNumber. A request that carries it returns InvalidArgument (HTTP 400) naming parent_pull_number rather than creating the pull request, so a client that kept sending it fails loudly instead of silently losing the stack parent. Migration: send parentPullRequest with a number member wherever your integration sent parentPullNumber.
+Added. Delete Pull Request Comment deletes a pull request comment by its Origin id: DELETE /v1/origin/repos/{ownerSlug}/{repoName}/pulls/comments/{commentId}. The comment's author can always delete it, and any other caller must hold write access to the repository through repository:contents:write or receives PermissionDenied (HTTP 403). Deleting the last comment of a thread removes the thread, deleting any other comment leaves the thread in place, and the comment's reactions and edit history go with it. An unknown or already-deleted id returns 404. Requires repository:pull_requests:reviews:write and costs 5 points.
+Added. Pull request responses carry a stack object holding the stack's id and the parentPullRequest this pull request is stacked on, absent when the pull request is not part of a stack and carrying no parentPullRequest on the root. Returned by List Pull Requests, Get Pull Request, Create Pull Request, Update Pull Request, and Merge Pull Request, and carried by every pull_request.* payload. A delivered stack reflects the topology as of the event that carried it.
+Added. Create Pull Request and Update Pull Request accept parentPullRequest, a selector that names the stack parent by number or id, or removes it with clear on update. Exactly one member must be set; an empty selector, clear: false, more than one member, and clear on create each return InvalidArgument (HTTP 400). The edit is an association only: no branch is rewritten, and base is retargeted only when it is sent too. Update applies it after base, so an explicit parent wins over the one a base change derives.
+Added. List Pull Requests accepts stackId, a stack id as returned in stack.id. It returns that stack's members in the requested sort order rather than stack order, so rebuild the stack from each member's stack.parentPullRequest. state still defaults to open, so pass state=all for the whole stack. A well-formed id that names no stack in the repository returns an empty list, and any other value returns InvalidArgument (HTTP 400).
+Added. List Pull Requests accepts headSha, the full 40- or 64-character hex SHA of a pull request head. It selects a pull request when any of its recorded versions has that head commit, current or superseded, so compare head.sha on each result to tell the two apart. Malformed, abbreviated, and unknown SHAs match nothing.
+Check runs
+Deprecated. checkRuns on the Batch Upsert Check Runs response is deprecated in favor of results[].checkRun and will be removed in a future release. It is still populated with the same runs in the same order. Migration: read results[].checkRun, which pairs each stored run with the outcome of its write.
+Added. Post Check Run returns outcome and Batch Upsert Check Runs returns results[], one per posted run in request order, each pairing checkRun with its own outcome. The value is created, updated, unchanged, or ignored_stale. A post whose externalUpdatedAt is older than the stored stamp is ignored, and a post that repeats the stored values changes nothing; both answer 200 with the stored run and leave updatedAt where it was, so outcome is the only way to tell them apart.
+Changed. A check run annotation message can contain Markdown, which Origin renders on the pull request page in both the Checks tab and the inline card on Changes. Accepted on Post Check Run and Batch Upsert Check Runs, and returned by Get Check Run. rawDetails stays plain text.
+Webhooks
+Added. pull_request.comment.reaction.added and pull_request.comment.reaction.removed are subscribable webhook events, delivered when a reaction is placed on or removed from a pull request comment. Their shared payload carries the pullRequest reference, a comment reference with its thread, and the reaction with its content and reactor. An add is delivered at least once: re-placing a reaction the reactor already holds delivers the event again for the same comment, reactor, and content, so fold on that triple. Removing a reaction the reactor does not hold delivers nothing.
 September 19, 2026
 Added. Delete Git Ref deletes a branch reference: DELETE /v1/origin/repos/{ownerSlug}/{repoName}/git/refs/{ref}. The path names the branch as refs/heads/<branch> or heads/<branch>, and only branch references can be deleted. A branch that does not exist returns 404; the repository default branch, a branch a deletion rule protects, and a repository whose contents are mirrored from another host each return FailedPrecondition (HTTP 400); and a branch whose tip moves while the delete is in flight returns FailedPrecondition (HTTP 400) or Aborted (HTTP 409 Conflict), so retry to delete the new tip. Pull requests whose head is the deleted branch are closed, as after a pushed deletion. Requires repository:contents:write and costs 5 points.
 Added. pull_request.label.added and pull_request.label.removed are subscribable webhook events, delivered when a label is assigned to or unassigned from a pull request. Their shared payload carries the pullRequest reference and the label snapshot, plus an actor naming the principal that assigned the label on pull_request.label.added only. Deleting a label definition delivers one pull_request.label.removed for every pull request that carried the label.
