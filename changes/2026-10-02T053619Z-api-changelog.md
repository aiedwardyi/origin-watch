 Origin API Changelog
 The Origin API is in Early Beta and subject to change. Review the OpenAPI specification when updating an integration.
 Changes to the Origin public API, including endpoints, request and response schemas, scopes, and webhooks, grouped by day with the newest first. Each change carries one label: Breaking, Deprecated, Added, Changed, or Removed. Breaking and deprecated changes include migration guidance inline. The Origin API reference always reflects the latest synced state.
+October 1, 2026
+Added. Replace Inbound IP Allowlist Entries replaces a namespace's allowlist entries with a complete set in one call: POST /v1/origin/namespaces/{namespaceSlug}/inbound-ip-allowlist/entries:replace. The body takes entries[], up to 1,000, each with a required cidr and optional description and enabled. Entries are matched by cidr as typed after trimming, with no normalization: a matched entry keeps its id, a new CIDR is added, and an omitted one is deleted. The call doesn't change whether the list is enforced. An optional etag rejects the call with Aborted (HTTP 409 Conflict) if the entries changed since that read, and an empty entries requires allowEmpty. The response carries the allowlist plus addedCount, updatedCount, removedCount, and unchangedCount. Requires a Cursor user credential holding namespace:settings:write and costs 10 points per call.
+Added. Get Inbound IP Allowlist and Update Inbound IP Allowlist responses carry etag, a version of the entry set that changes whenever an entry is added, updated, or removed.
+Changed. The reference and the OpenAPI specification describe the parameters of every ruleset rule type, where they used to say only that the shape depends on ruleType. The specification adds one schema per shape, such as RulesetPullRequestParameters and RulesetRequireStatusChecksParameters, linked from parameters on rules in the requests and responses of Create Ruleset, Update Ruleset, Get Ruleset, and List Rulesets. ruleType lists all nine rule types: pull_request, require_status_checks, and require_branch_up_to_date for merge_branch rulesets, and deletion, non_fast_forward, block_direct_updates, block_merges, ref_name_pattern, and required_linear_history for push rulesets. The wire format and validation are unchanged.
 September 30, 2026
 Breaking. Create Ruleset and Update Ruleset reject a rule whose ruleType never runs in the ruleset's kind with InvalidArgument (HTTP 400), where Origin used to store the rule and never run it. A merge_branch ruleset accepts only the merge rule types pull_request, require_status_checks, and require_branch_up_to_date, and a push_branch, push_tag, or push_repository ruleset accepts only push-time rule types, such as deletion and non_fast_forward. An update that sends back a mismatched rule the ruleset already stores fails the same way. Migration: move each rule into a ruleset of the kind it runs in before you call Create Ruleset or Update Ruleset.
 Breaking. Transition Repo Mirror returns FailedPrecondition (HTTP 400) for an inbound_to_outbound transition unless outbound mirroring is enabled for the repository. The reference and the OpenAPI specification no longer describe outbound mirroring: Force Repo Mirror Cutover and the inbound_to_outbound and outbound_to_inbound transitions, announced on September 11, were removed, as was the outbound value of mirror.status. Repositories already mirroring outbound keep working. Migration: keep mirrored repositories inbound, and send Transition Repo Mirror only initial_to_inbound, which retries a mirror whose initial sync failed.
