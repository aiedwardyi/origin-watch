 Origin API Changelog
 The Origin API is in Early Beta and subject to change. Review the OpenAPI specification when updating an integration.
 Changes to the Origin public API, including endpoints, request and response schemas, scopes, and webhooks, grouped by day with the newest first. Each change carries one label: Breaking, Deprecated, Added, Changed, or Removed. Breaking and deprecated changes include migration guidance inline. The Origin API reference always reflects the latest synced state.
+September 29, 2026
+Pull requests
+Breaking. Update Pull Request no longer reopens a pull request whose head branch was deleted. Setting state to "open" or draft to false on such a closed pull request returns FailedPrecondition (HTTP 400) and leaves it closed, where Origin used to reopen it with no head to read. Migration: push the head branch again before you reopen the pull request.
+Changed. potentialMergeCommit.baseSha is also set when state is merge_conflict, naming the base branch tip the merge conflicted with; it used to be set only when state is prepared. A conflict recorded before this change can still omit it. Returned in version by List Pull Requests, Get Pull Request, Create Pull Request, Update Pull Request, and Merge Pull Request, and carried by the pull_request.* lifecycle payloads.
+Grants and SSH certificate authorities
+Breaking. The namespace grant and SSH certificate authority endpoints moved from /v1/origin/owners/{ownerSlug} to /v1/origin/namespaces/{namespaceSlug}, and the old paths were removed: List Namespace Grants, Upsert Namespace Grant, Delete Namespace Grant, List SSH Certificate Authorities, Add SSH Certificate Authority, Delete SSH Certificate Authority, and Set SSH Certificate Requirement. Migration: replace /v1/origin/owners/{ownerSlug} with /v1/origin/namespaces/{namespaceSlug} in those requests, keeping the same slug and the rest of the path.
+Check runs
+Added. Check runs can report the status failing for a run that keeps going after a step failed. Post it with Post Check Run or Batch Upsert Check Runs without a conclusion, then post completed with the verdict when the run ends. A failing run counts as pending for required checks and expires at its deadlineAt like an in_progress run. List Check Runs For Commit accepts failing as a status filter, and check run responses and webhook payloads can carry it.
+Added. repository.check_run.updated is delivered when a post updates a check run without completing it, leaving it queued, in_progress, or failing, including a post that reopens a completed run. It carries the check run payload and requires repository:checks:read.
+Added. repository.check_run.annotations.created is delivered once for each Create Check Run Annotations request, with the annotations it added. It carries the check run annotations payload and requires repository:checks:read.
+Changed. A post that reopens a timed-out check run as in_progress or failing without its own deadlineAt gets the expired deadline back, so the next sweep times the run out again and delivers another repository.check_run.completed. Before, the reopened run kept no deadline and never expired. To keep the run open, send a new deadlineAt with that post; see Timestamps and deadlines.
+Commits and contents
+Added. List Commits accepts since and until, RFC 3339 timestamps that bound the listing by committer time, inclusive and in whole seconds. A malformed timestamp, or a since later than until, returns InvalidArgument (HTTP 400). The listing ends once it reads 100 consecutive commits older than since, as git log --since does, and page tokens carry both bounds.
+Inbound IP allowlist
+Added. Get Inbound IP Allowlist returns a namespace's inbound IP allowlist: GET /v1/origin/namespaces/{namespaceSlug}/inbound-ip-allowlist. The response carries enabled, whether the list is enforced, and entries[], every entry oldest first, each with id, cidr, description, enabled, and createdAt. It is not paginated, since a namespace lists at most 100 entries. Allowlists are available on team namespaces that have the feature enabled, and any other namespace returns FailedPrecondition (HTTP 400). Requires namespace:settings:read.
+Added. Update Inbound IP Allowlist turns enforcement of a namespace's allowlist on or off and returns the allowlist: PATCH /v1/origin/namespaces/{namespaceSlug}/inbound-ip-allowlist. The body takes a required enabled boolean. While the list is enforced and at least one entry is enabled, git over SSH and HTTPS, the API, and file downloads on the namespace's repositories accept a Cursor user's requests only from listed addresses; app JWTs, installation access tokens, installation user tokens, and service accounts are not restricted. Enabling a list that excludes the caller's own address returns InvalidArgument (HTTP 400), and setting the current value succeeds without change. Every allowlist write from a caller the enforced list already excludes returns PermissionDenied (HTTP 403). Requires a Cursor user credential holding namespace:settings:write.
+Added. Add Inbound IP Allowlist Entry adds an IPv4 or IPv6 address or CIDR range to a namespace's allowlist and returns the entry with its id: POST /v1/origin/namespaces/{namespaceSlug}/inbound-ip-allowlist/entries. The body takes a required cidr, stored as spelled after trimming surrounding whitespace, an optional description of at most 255 characters, and an optional enabled that defaults to true. A cidr the namespace already lists with the same spelling returns AlreadyExists (HTTP 409 Conflict). A cidr that does not parse, a /0 range, or an add to a list already holding 100 entries returns InvalidArgument (HTTP 400). Requires a Cursor user credential holding namespace:settings:write.
+Added. Get Inbound IP Allowlist Entry returns one entry by its id: GET /v1/origin/namespaces/{namespaceSlug}/inbound-ip-allowlist/entries/{entryId}. An ID the namespace does not list returns 404. Requires namespace:settings:read.
+Added. Delete Inbound IP Allowlist Entry removes an entry by its id and answers 204 No Content: DELETE /v1/origin/namespaces/{namespaceSlug}/inbound-ip-allowlist/entries/{entryId}. Removing the entry that admits the caller's own address from an enforced list returns InvalidArgument (HTTP 400). Requires a Cursor user credential holding namespace:settings:write.
+Added. Update Inbound IP Allowlist Entry changes an entry's cidr, description, or enabled by its id: PATCH /v1/origin/namespaces/{namespaceSlug}/inbound-ip-allowlist/entries/{entryId}. Omitted fields keep their stored values, and a new cidr keeps the entry's id. A cidr another entry already uses returns AlreadyExists (HTTP 409 Conflict), and a change that would exclude the caller's own address from an enforced list returns InvalidArgument (HTTP 400). Requires a Cursor user credential holding namespace:settings:write.
 September 27, 2026
 Changed. A pageSize sent with a pageToken applies to that page, and a follow-up request that omits pageSize keeps the previous page size, on List App Installation Repositories, List Branches, List Check Run Annotations, List Check Runs For Commit, List Check Runs For Suite, List Check Suites For Commit, List Commit Files, List Comparison Files, List Namespace Grants, List Namespaces, List Pull Request Files, List Pull Requests, List Repos, and List Repository Grants. List Commit Files and List Comparison Files no longer reject a follow-up pageSize that differs from the first request's with InvalidArgument (HTTP 400), and the other endpoints no longer ignore it. Everything else a page token is bound to, such as the repository, filters, and pull request version, still has to match.
 September 26, 2026
 Changed. Merge Pull Request returns Aborted (HTTP 409 Conflict) instead of InvalidArgument (HTTP 400) when the pull request's head branch has moved past the head of its latest version, for example because a push landed that Origin had not yet recorded as a new version. That is the same answer as a stale expectedHeadSha. Nothing merges in either case; retry after Get Pull Request reports the new head in version.headSha.
 September 25, 2026
-Pull requests
 Breaking. Comment thread and review version references no longer carry createdAt; they hold only the version's number, headSha, and baseSha. This covers thread.version on List Pull Request Comments, Get Pull Request Comment, Create Pull Request Comment, and Update Pull Request Comment, version on Update Pull Request Thread, pullRequestVersion on List Pull Request Reviews, Create Pull Request Review, Update Pull Request Review, and Dismiss Pull Request Review, and the same fields in the pull_request.comment.created and pull_request.review.* payloads. Migration: wherever your integration read createdAt from a thread or review version, read it from version on Get Pull Request or on the pull_request.* lifecycle payload that recorded that version, matching on number.
 Added. Pull request versions carry potentialMergeCommit, Origin's test merge of that version: state is prepared, merge_conflict, or unknown, and a prepared merge adds the merge commit's sha and the base branch tip baseSha it was built on. Returned in version by List Pull Requests, Get Pull Request, Create Pull Request, Update Pull Request, and Merge Pull Request, and carried by the pull_request.* lifecycle payloads, so a webhook receiver learns the merge preview without calling Get Git Ref. An event carries the value as of its emission, so treat unknown as not yet known and re-read the pull request.
-Apps and installations
 Added. Create Installation User Token mints an installation user token that acts on behalf of an eligible namespace member: POST /v1/origin/app/installations/{installationId}/user_access_tokens. Requires an app JWT and an installation granted namespace:user_tokens:write. Name the user with userId or userEmail; optional scopes and repositoryIds narrow access. The token expires within 15 minutes and never outlives the app JWT.
 Added. User actors can include performedVia.app with the app's id and optional displayName when an app acted on the user's behalf. The field is absent for direct user actions and can be absent when delegation data is unavailable. See Acting on behalf of users.
-Commits and contents
 Added. List Commits accepts authorEmails and committerEmails filters, with up to 100 distinct emails each. Matching ignores case and surrounding whitespace; a commit must match both lists when both are set. A filtered page can be empty and still have a nextPageToken, so keep paging until the token is empty.
-Check runs
 Changed. A cancelled check run no longer displaces a passing result. A completed post with the conclusion cancelled to a run that is completed with success, neutral, or skipped is ignored as stale whatever its externalUpdatedAt, so Post Check Run and Batch Upsert Check Runs answer 200 with the stored run and the outcome ignored_stale. A cancellation posted as a new run attempt or suite attempt ranks below the passing attempt instead, so List Check Runs For Commit, List Check Suites For Commit, List Check Runs For Suite, and Get Pull Request Mergeability keep reporting the pass. A newer failure still replaces a pass, and a cancellation still applies over a failing or pending run; Attempts and the current attempt has the full rule.

 September 24, 2026
 Added. List Namespaces lists the namespaces you can list repositories in, ordered by slug: GET /v1/origin/namespaces. The candidates are your teams' namespaces, your personal namespace, and the namespaces holding repositories you were granted, and only those on which you hold namespace:repositories:read are returned, so each namespace.slug is a valid ownerSlug for List Repos. Each entry's viewerCanCreateRepositories says whether Create Repo in that namespace would pass authorization and the owner's plan and settings checks for you. Pages hold 30 namespaces by default and at most 100. Requires a Cursor user credential and no scope, and costs 1 point; app tokens, installation tokens, and service accounts receive PermissionDenied (HTTP 403).
